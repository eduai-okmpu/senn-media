# senn.cute — automated Reels runbook

Instagram account: **senn.cute** (Windsor connector `instagram`, account id `17841428545693499`).
Audience/time zone of the owner: Asia/Almaty. Content language: English. Style: quiet, soft, cinematic.

Nobody is watching a scheduled run. Never ask questions; decide, act, and report at the end.
If something fails, record it (queue status + report) instead of looping.

## Hard rules
- Publish **at most one** queue item per run, and only items from `content/queue.json`.
- Never delete Instagram posts or repo files. Never change schedules.
- All media is generated by `tools/reel.py` (original music, original scene, original text).
  Do not use real song audio, third-party footage, or quotes attributed to real people.
- Never claim success unless the Windsor call returned "Published video post (Reel) ...".

## Setup (every run, fresh session)
1. `mcp__claude-code-remote__add_repo` owner `eduai-okmpu`, repo `senn-media`, access `push`.
2. If `/home/claude/senn-media/.git` does not exist: `git clone --depth 1 https://github.com/eduai-okmpu/senn-media /home/claude/senn-media`
   (generous timeout, one clone only). Then `register_repo_root`. Work inside that directory.
3. `git config user.name Claude; git config user.email noreply@anthropic.com`
4. Load Windsor tools: ToolSearch `select:mcp__Windsor_ai_for_Social_Media__execute_action,mcp__Windsor_ai_for_Social_Media__get_data,mcp__Windsor_ai_for_Social_Media__get_fields`.
   If these tools do not exist in the session, still generate and push the video, leave the item as `pending`,
   and report that Instagram access was missing.

## Publisher run (Mon / Wed / Fri)
1. `python3 tools/queue.py next` → JSON item. Exit code 3 = queue empty → report and stop.
2. If `status == "publishing"` (a previous run died mid-way): use Windsor `get_data` (connector `instagram`,
   fields `media_id, timestamp, media_caption, media_permalink`, last 14 days) and look for the item's caption.
   Found → `queue.py mark <id> published <media_id>`, commit, push, stop (this run's slot is used).
   Not found → `queue.py mark <id> pending` and continue.
3. Generate (lines are separate arguments):
   `python3 tools/reel.py --out reels/<id>.mp4 --palette <palette> --seed <seed> --lines "<l1>" "<l2>" ...`
   Takes ~50 s. Exit code must be 0 and `qa_pass` true. Otherwise retry once with `--seed <seed+100>`;
   if it fails again → `queue.py mark <id> failed`, commit, push, report, stop.
4. Look at the `preview` JPG from the JSON (Read tool): text must be readable and fully inside the frame.
   If not, treat as a failed generation (step 3 rule).
5. `queue.py mark <id> publishing`; `git add reels/<id>.mp4 content/queue.json`; commit; `git push origin main`.
   Verify `git ls-remote origin refs/heads/main` equals `git rev-parse HEAD`. (A "push negotiation failed"
   warning is harmless if the push itself succeeds.)
6. Publish with `execute_action`: connector `instagram`, action `create_video_post`, account `17841428545693499`,
   params `{"video_url": "https://raw.githubusercontent.com/eduai-okmpu/senn-media/main/reels/<id>.mp4",
   "caption": "<caption from item>", "share_to_feed": true, "thumb_offset": 5000}`.
   If the error says the video URL could not be fetched, wait 60 s and retry once (GitHub raw can lag a few seconds).
7. Success → `queue.py mark <id> published <media_id>`; commit; push. Failure → `queue.py mark <id> failed`; commit; push.
8. Final message: item id, media id (or error), pending count (`queue.py pending`).

## Weekly report run (Sunday)
1. With Windsor `get_data` (connector `instagram`): reels of the last 28 days
   (`date, media_caption, media_permalink, media_views, media_reach, media_like_count, media_comments_count,
   media_saved, media_shares, media_reel_skip_rate, media_reel_avg_watch_time`) and account totals
   (`date, views, views_followers, views_non_followers, reach_non_followers, follower_count, followers_count`).
   Call `get_fields` first if a field name is rejected.
2. Match each reel to its queue item (caption text) and compare palettes, phrase styles, caption CTAs.
   Be honest about small samples; do not claim trends from fewer than ~6 posts.
3. Write `content/report-YYYY-MM-DD.md`: totals, best/worst post, what to try next. Keep it under 40 lines.
4. If `queue.py pending` < 5: write 6 new original items to a temp JSON file and run `queue.py add <file>`.
   Item = `{"id": "NNN-slug", "lines": [title, up to 3 short lines], "caption": "...", "palette": dusk|dawn|night|mist, "seed": <new int>}`.
   Phrases: original, quiet/soft/gentle tone, title ≤ 28 characters per line where possible, English.
   Caption = phrase + one call to action (save/send/tag) + 3 narrow hashtags
   (e.g. #quietmoments #softaesthetic #slowliving #littlemoments #gentlereminders #slowdown). Unique ids and seeds.
   Lean toward palettes and tones that performed better.
5. Commit (`content/` only) and push. Final message: 5-line summary of results and what was added.

## Manual use
`python3 tools/queue.py show` lists everything. To add your own phrase, append an item to `content/queue.json`
(status `pending`). To skip an item: `python3 tools/queue.py mark <id> skipped`.
